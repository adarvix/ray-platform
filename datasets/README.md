# Source datasets

Generated by [`app/corpreg/datagen.py`](../app/corpreg/datagen.py) (`seed=42`; regenerate with `cd app && python -m corpreg.datagen --out ../datasets`). The pipeline regenerates identical files when `GENERATE_SOURCES=true`.

| File | Rows | Represents |
|---|---|---|
| `supply_chain.csv` | 1,200 | Procurement's supplier master: operational facts, **no revenue** |
| `financial.csv` | 1,200 | Finance's filings feed: revenue, margin, founding year; ~10% of rows have revenue missing (the model predicts these) |
| `ground_truth.csv` | 2,400 | `source_record_id → entity_id`. Used **only** to measure resolution precision/recall, never for matching |

**supply_chain.csv:** `supplier_id, company_name, country, city, industry, website, employee_count, active_contracts, annual_spend_usd, onboarded_date`

**financial.csv:** `filing_id, legal_name, country, headquarters_city, sector, website, ticker, fiscal_year, founded_year, reported_employees, annual_revenue_usd, operating_margin`

The two sources describe 1,500 underlying companies, about 55% of which appear in both. There is **no shared key**, and the noise is deliberate, to make entity resolution non-trivial:
- Legal suffixes vary (`Inc.` / `Incorporated` / `Corp`, `Ltd` / `Limited` / `PLC`, `GmbH`, `Pvt Ltd`, `Pte. Ltd.`).
- Casing varies (UPPER, lower), abbreviations appear (`Intl`, `Mfg`, `Sys`), and `&` vs `and`.
- About 8% of names contain a single-character typo.
- Websites appear in different formats (`https://www.x.com/`, `x.com`), and are missing for 25–35% of rows.
- Each source has about 4% internal duplicates.
- Near-collisions exist: different companies with names one character apart (`Apexridge Retail` vs `Apexbridge Retail`).

Revenue is generated as a function of employees × sector productivity × company maturity × noise, so a model can learn it from the harmonized features.
